Tema 1: ¿Qué significa programar?

Cuando empezamos en SMR, muchos pensamos que programar consiste exclusivamente en escribir líneas de código extrañas en pantallas oscuras. ¡Nada más lejos de la realidad! En nuestro día a día profesional, programar es, ante todo, automatizar tareas repetitivas y resolver problemas técnicos de manera lógica.

🍳 La Analogía de la Cocina:
  • El Problema: Tengo hambre y quiero cenar una tortilla de patatas.
  • El Algoritmo: La receta paso a paso escrita en un papel en castellano claro.
  • El Programa: La misma receta adaptada digitalmente a las órdenes estrictas que entiende un robot de cocina.

1.1. Problema, Algoritmo, Programa y Lenguaje

Es muy importante no confundir estos cuatro conceptos clave:

  • Problema: La necesidad real a resolver (ej. "Necesito comprobar qué ordenadores del aula tienen menos de 8 GB de RAM").
  • Algoritmo: La secuencia ordenada de pasos lógicos para solucionarlo (entendible por personas).
  • Programa: El algoritmo traducido a un lenguaje informático específico.
  • Lenguaje de Programación: El vocabulario y sintaxis permitidos (en nuestro ciclo utilizaremos Java).

1.2. El Modelo Entrada - Proceso - Salida (E-P-S)

Casi cualquier programa informático funciona bajo este esquema mental imbatible:

📥

1. ENTRADA (Input)

Los datos que el sistema recibe del exterior (ej. Leer la RAM de un PC: 4 GB).

⚙️

2. PROCESO (Process)

Las operaciones matemáticas o comparaciones lógicas (ej. ¿Es la RAM menor que 8?).

📤

3. SALIDA (Output)

El resultado devuelto al usuario (ej. Mostrar en pantalla: "Ampliación recomendada").

Tema 2: Descomposición, Patrones y Abstracción

Para resolver problemas informáticos complejos sin volverte loco, utilizamos el Pensamiento Computacional, apoyándonos en tres pilares fundamentales:

2.1. Descomposición: Divide y vencerás

Intentar programar una aplicación entera de golpe es un error seguro. Descomponer consiste en trocear un problema gigantesco (ej. construir el software SMR Manager) en subproblemas pequeños que podamos programar y probar por separado con total comodidad.

  • Inventario de equipos (altas y consultas).
  • Gestión y registro de incidencias técnicas.
  • Validación de parámetros de red (IPs y MACs).

2.2. Reconocimiento de Patrones

Un patrón es una estructura común que se repite en situaciones muy diferentes. Al detectarlos, no necesitamos reinventar la rueda; reutilizamos la misma lógica con diferentes datos.

Patrón Común (Ej. Registrar Equipo / Registrar Incidencia):

Pedir Datos → Validar Formato → Almacenar en Base de Datos → Confirmar Éxito

2.3. Abstracción: Quedarse con lo que importa

Abstraer es el arte de ignorar el ruido irrelevante y conservar únicamente la información estrictamente necesaria para resolver nuestro objetivo actual.

🗺️ Ejemplo del Mapa de Metro:

Un plano de metro no dibuja las alcantarillas, las piedras ni las curvas exactas de las calles. Solo muestra las estaciones y las líneas conectadas porque es lo único que te importa para viajar. En programación ocurre exactamente igual con nuestros datos.

Tema 3: Algoritmos, Pseudocódigo y Diagramas de Flujo

Antes de escribir código real en Java, necesitamos diseñar la hoja de ruta mediante un algoritmo riguroso y ordenado.

3.1. Pseudocódigo: El idioma intermedio

El lenguaje natural (español cotidiano) es demasiado ambiguo (¿qué significa exactamente "si tiene poca RAM, avisa"?). El pseudocódigo nos ofrece un formato estructurado y limpio que elimina ambigüedades sin exigir la sintaxis estricta de Java.

INICIO
  LEER ram
  SI ram >= 8 ENTONCES
    ESCRIBIR "RAM suficiente"
  SINO
    ESCRIBIR "Ampliación recomendada"
  FIN_SI
FIN

3.2. Las Tres Estructuras Fundamentales

Cualquier software del mundo se construye combinando únicamente estas tres estructuras de control:

  1. Secuencia: Instrucciones que se ejecutan linealmente una detrás de otra.
  2. Decisión (Alternativa): Bifurcaciones condicionales mediante estructuras tipo `SI ... SINO`.
  3. Repetición (Bucles): Instrucciones que se repiten varias veces mediante `MIENTRAS` o `PARA`.

3.3. Diagramas de Flujo y Trazas

Los diagramas de flujo representan gráficamente los algoritmos utilizando formas normalizadas (óvalos de inicio/fin, rectángulos de proceso, rombos de decisión y paralelogramos de E/S). Por su parte, realizar una traza consiste en simular manualmente en una tabla el comportamiento del algoritmo con datos de prueba (incluyendo siempre casos límite) para comprobar si funciona antes de pasarlo al ordenador.

Resumen Final: Puntos Clave de Estudio

Repasa rápidamente los conceptos imprescindibles para superar con éxito la evaluación de la UT1:

1. Programar es Resolver

El proceso lógico empieza comprendiendo la necesidad y diseñando la solución en papel antes de abrir el entorno de desarrollo en Java.

2. Los 4 Pilares del Pensamiento Computacional

Descomposición (trocear problemas), Reconocimiento de Patrones (reutilizar estructuras), Abstracción (filtrar lo irrelevante) y Algoritmos (pasos ordenados).

3. El Modelo E-P-S

Toda arquitectura informática procesa Entradas (datos), realiza un Proceso (condiciones y cálculos) y produce una Salida (resultados).

4. Diseño Lógico y Verificación

El uso de Pseudocódigo, Diagramas de Flujo y Trazas con valores límite garantiza que el algoritmo no tenga fallos lógicos ocultos.
