Tema 1: ¿Qué significa programar?

En este primer tema, exploraremos los cimientos de la programación, centrándonos en el pensamiento computacional y en cómo estructurar las soluciones antes incluso de tocar una línea de código.

1.1. Conceptos Fundamentales

A menudo, la gente confunde estos términos. Es vital tener clara la diferencia:

  • Problema: Es la necesidad que queremos resolver. (Ejemplo: Decidir si un ordenador de nuestra aula necesita que le ampliemos la memoria RAM).
  • Algoritmo: Son los pasos ordenados y exactos para solucionar ese problema. Todavía puede estar escrito en un lenguaje que entendamos los humanos.
  • Programa: Es el algoritmo anterior, pero expresado en un lenguaje de programación específico, de modo que el ordenador pueda ejecutarlo.
  • Lenguaje de Programación: Es el conjunto de reglas y vocabulario que usamos para escribir los programas. En este curso, más adelante, utilizaremos Java.

Secuencia de trabajo habitual:

  1. Entender el problema.
  2. Diseñar el algoritmo.
  3. Escribir el programa (código).
  4. Probar y corregir errores.
💡 Idea Clave: Programar no empieza escribiendo código en Java; empieza entendiendo profundamente el problema y diseñando la solución correcta.

1.2. El Pensamiento Computacional

Pensar de manera computacional significa plantear un problema de tal forma que podamos construir una solución que sea clara, que se pueda comprobar y, en última instancia, que se pueda automatizar mediante un ordenador.

Este pensamiento se apoya en cuatro pilares básicos:

  • Descomposición: ¿En qué partes más pequeñas e independientes puedo dividir este gran problema?
  • Reconocimiento de Patrones: ¿Qué partes de este problema se parecen a otros problemas que ya he resuelto antes?
  • Abstracción: ¿Qué información es verdaderamente importante para este objetivo en concreto y qué detalles puedo ignorar?
  • Algoritmos: ¿Cuáles son los pasos exactos, ordenados y finitos que resuelven el problema?

1.3. El Modelo Entrada - Proceso - Salida (E-P-S)

Casi cualquier programa informático, desde el más sencillo hasta el más complejo, puede entenderse usando este modelo.

  • ENTRADA (Input): Son los datos iniciales que recibe el sistema o programa.
  • PROCESO (Process): Son las operaciones, cálculos y decisiones que el programa realiza con esos datos de entrada.
  • SALIDA (Output): Es el resultado final que produce el programa después de procesar la información.

Ejemplo 1: Comprobar RAM

  • Entrada: RAM instalada (ej. 4 GB).
  • Proceso: Comparar RAM con mínimo (8 GB). ¿Es menor?
  • Salida: Mensaje "Ampliación recomendada" o "RAM suficiente".

Ejemplo 2: Espacio en disco

  • Entrada: Capacidad total y espacio ocupado.
  • Proceso: Restar ocupado a total.
  • Salida: Gigabytes (GB) libres.

Tema 2: Descomposición, Patrones y Abstracción

En este tema profundizaremos en los tres primeros pilares del pensamiento computacional aplicándolos al diseño de un modelo manejable.

2.1. Descomposición de Problemas

Intentar resolver un problema gigante "todo a la vez" suele llevarnos a errores y confusión. Descomponer significa dividir un problema grande en subproblemas más pequeños que sean funcionales, que podamos entender, programar y probar por separado.

Ejemplo: El proyecto SMR Manager

Imagina que tenemos que crear una aplicación para gestionar los equipos informáticos del instituto. Problema general: "SMR MANAGER". Podemos descomponerlo en áreas funcionales:

  • Inventario: Alta y consulta de equipos.
  • Incidencias: Registrar y consultar averías.
  • Validaciones: Comprobar que las direcciones IP o MAC son correctas.
  • Informes: Generar listados.

¿Qué es una "buena" o "mala" descomposición? Debemos buscar piezas que tengan un significado propio y cumplan una función del sistema.

  • Mala descomposición (microscópica): Mover el ratón, hacer clic izquierdo, pulsar la tecla A. (Esto son acciones, no funciones).
  • Buena descomposición (funcional): Registrar un nuevo equipo, Validar una dirección IP, Crear una incidencia.

2.2. Reconocimiento de Patrones

Un patrón es una estructura o forma de resolver las cosas que se repite en diferentes situaciones. Identificarlos nos permite reutilizar ideas.

Ejemplo de Patrón:

Fíjate en las similitudes entre registrar un equipo y registrar una incidencia:

  • Registrar un EQUIPO: Pedir datos → Validar datos → Guardar en BD → Confirmar.
  • Registrar una INCIDENCIA: Pedir datos → Validar datos → Guardar en BD → Confirmar.

Aunque los datos sean diferentes, la estructura es la misma.

Patrones comunes en programación:

  • Validar: Comprobar si un dato es correcto antes de continuar.
  • Buscar: Recorrer una lista de datos hasta encontrar lo que buscamos.
  • Filtrar: De una lista grande, quedarnos solo con los elementos que nos interesan.
  • Contar: Recorrer elementos y sumar los que cumplen una condición.

2.3. Abstracción

Abstraer es el arte de quedarse únicamente con la información que es relevante para nuestro objetivo actual, eliminando todo el "ruido" o detalles innecesarios.

Ejemplo: Abstracción al comprobar la RAM de un PC

  • Datos RELEVANTES: Cuánta RAM tiene instalada, Cuánta RAM mínima necesitamos.
  • Datos IRRELEVANTES: El color de la torre, la marca del teclado, la temperatura del aula.

Si estuviéramos programando un sistema de climatización, la temperatura del aula sí sería relevante, pero para ver la RAM, debemos ignorarla.

Tema 3: Algoritmos, Pseudocódigo y Diagramas de Flujo

Una vez que hemos analizado el problema, necesitamos plasmar la solución de una forma clara antes de escribir código Java.

3.1. Propiedades de un Algoritmo

Recuerda que un algoritmo es una secuencia finita y ordenada de instrucciones. Debe cumplir esto:

  1. Objetivo Claro: Sabemos exactamente qué problema resuelve.
  2. Ordenado: Los pasos tienen una secuencia lógica (no puedes meter la pizza al horno antes de prepararla).
  3. Precisión (No ambiguo): Cada paso debe ser claro. Si decimos "Poca RAM", es ambiguo. Si decimos "RAM < 8 GB", es preciso.
  4. Finito: Tarde o temprano, el algoritmo tiene que terminar; no puede quedarse atascado para siempre.

3.2. Pseudocódigo

El lenguaje natural es muy ambiguo. El pseudocódigo es un paso intermedio: no es código real, pero tiene una estructura parecida que nos ayuda a pensar.

Palabras clave:

  • INICIO / FIN: Empieza/acaba.
  • LEER dato: Pedir dato (Entrada).
  • ESCRIBIR msj: Mostrar (Salida).
  • SI ... SINO: Decisiones.
  • MIENTRAS / PARA: Bucles.

Ejemplo (Comprobación RAM):

INICIO
  LEER ram
  SI ram >= 8 ENTONCES
    ESCRIBIR "RAM suficiente"
  SINO
    ESCRIBIR "Ampliación"
  FIN_SI
FIN

3.3. Estructuras Fundamentales

Casi todos los programas del mundo se construyen combinando estas tres ideas:

  1. Secuencia: Las instrucciones se ejecutan una detrás de otra.
  2. Decisión (Condicionales): El programa evalúa una condición y elige un camino u otro. (El SI ... SINO).
  3. Repetición (Bucles): Se ejecutan instrucciones varias veces. (El MIENTRAS o PARA).

3.4. Diagramas de Flujo

Son la representación visual de nuestro algoritmo. Usamos formas geométricas:

Inicio / Fin
Entrada / Salida
Proceso
Decisión

3.5. La Traza de Ejecución

Una traza consiste en simular nosotros mismos cómo ejecutaría el ordenador el algoritmo, usando datos inventados en una tabla.

Ejemplo Traza (`RAM >= 8`):

Entrada (RAM) Condición: ¿RAM >= 8? Salida Esperada
16Sí (Verdadero)"RAM suficiente"
4No (Falso)"Ampliación recomendada"
8 (Límite)Sí (Verdadero)"RAM suficiente"

Probar un valor límite (como el 8) es fundamental para detectar errores.

Resumen Final: Lo más importante

Este resumen sintetiza los conceptos clave de la UT1 que debes dominar antes de empezar a programar en código real.

1. La base de la Programación

Programar es resolver problemas, no solo teclear. El proceso empieza por entender la necesidad y diseñar una solución. El código es solo el último paso.

2. Pensamiento Computacional (4 pilares)

  • Descomponer: Dividir problemas gigantes en piezas pequeñas manejables.
  • Reconocer Patrones: Aprovechar estructuras que se repiten.
  • Abstraer: Centrarse solo en los datos necesarios, ignorando el resto.
  • Diseñar Algoritmos: Crear la receta paso a paso para la solución.

3. Análisis y Diseño

El Modelo E-P-S: Todos los procesos se reducen a: recibir datos (Entrada), realizar cálculos/decisiones (Proceso), y devolver un resultado (Salida).

Características del Algoritmo: Preciso, ordenado y finito.

4. Herramientas Previas al Código

  • Pseudocódigo: Lenguaje intermedio estructurado (INICIO, LEER, SI...).
  • Diagramas de Flujo: Representación visual mediante formas geométricas.

Las Trazas: Pruebas manuales simulando el algoritmo, vitales para comprobar la lógica (especialmente valores límite).

5. Las 3 Estructuras Básicas

El flujo de un programa se basa en Secuencias (paso a paso), Decisiones (SI...SINO) y Repeticiones (Bucles).
